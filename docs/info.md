## How it works

This project is an entry in Jane Street's protocol emulator ASIC competition: a small, reprogrammable
CPU that bit-bangs serial protocols from firmware instead of using a fixed-function block per protocol.

The core (`src/cpu.v`) is a single-issue, cycle-exact CPU. Every instruction takes one clock, except
`WAIT n`, which takes `1 + n`. That makes protocol timing a matter of counting cycles in the program.
The instruction set is in `docs/isa.md`. It can read 16 input pins, drive 8 output pins, shift bits
through a carry flag, loop, and branch on a pin.

The firmware lives in `src/rom.v`, generated by `tools/build_rom.sh` from `firmware/*.asm`. At boot a
small dispatcher reads the MODE pin (`uio[7]`) and jumps to one of two programs:

- **MODE = 0: UART transmitter**, 8N1 at 434 clocks per bit (50 MHz / 115200 baud).
- **MODE = 1: SPI master**, mode 0, MSB first, 16-bit frames. It sends `ui[7:0]`, receives a byte
  from the slave, and sends the received byte straight back as a built-in self-test.

Same silicon, two protocols, chosen by firmware. The original fixed-logic UART
(`reference/uart_tx_fixed.v`) is kept as a reference design.

## How to test

Set MODE (`uio[7]`) **before reset**, then in either mode:

1. Put a byte on `ui[7:0]`.
2. Raise `uio[0]` (START) and hold it. The firmware runs one transfer, then waits for START to go low.

UART (MODE = 0): watch `uo[0]` (TX); `uo[1]` is BUSY.

SPI (MODE = 1): `uo[0]` = CS_N, `uo[1]` = SCK, `uo[2]` = MOSI, `uo[3]` = BUSY, and `uio[1]` = MISO.

Simulation tests live in `test/` and run with `make` using cocotb and Icarus Verilog. They include a
cycle-exact UART bit-timing check and an SPI test against a simulated slave.

## External hardware

A USB-to-serial adapter or logic analyzer on the output pins; any SPI slave for SPI mode.
