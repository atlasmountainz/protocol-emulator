## How it works

This project is an entry in Jane Street's protocol emulator ASIC competition: a small, reprogrammable
CPU that bit-bangs serial protocols from firmware instead of using a fixed-function block per protocol.

The core (`src/cpu.v`) is a single-issue, cycle-exact CPU. Every instruction takes one clock, except
`WAIT n`, which takes `1 + n`. That makes protocol timing a matter of counting cycles in the program.
The instruction set is in `docs/isa.md`. It can read 16 input pins, drive 8 output pins, shift bits
through a carry flag, loop, and branch on a pin.

The firmware lives in `src/rom.v`, generated by `tools/asm.py` from `firmware/uart_tx.asm`. The current
program is an 8N1 UART transmitter at 434 clocks per bit (50 MHz / 115200 baud). A cocotb test checks
that every bit is exactly 434 cycles long. The original fixed-logic UART (`reference/uart_tx_fixed.v`)
is kept as a reference design.

## How to test

With the UART firmware:

1. Put a byte on `ui[7:0]`.
2. Raise `uio[0]` (START) and hold it. The firmware sends one byte and then waits for START to go low.
3. Watch `uo[0]` (TX) for the frame. `uo[1]` (BUSY) is high until the stop bit finishes.

Simulation tests live in `test/` and run with `make` using cocotb and Icarus Verilog.

## External hardware

A USB-to-serial adapter (or logic analyzer) on `uo[0]` to receive the UART output.
